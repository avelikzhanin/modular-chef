## 1. Концепция

**Название (рабочее):** Modular Chef
**Одной фразой:** «Выбери, что хочешь есть — приложение соберёт из этого 2 недели разнообразных блюд, скажет, что купить, как приготовить и как сохранить свежим.»

**Целевая аудитория:** люди, которые делают мил-преп (готовят впрок раз в неделю), но не знают, что планировать, как разнообразить и как правильно хранить заготовки.

**Уникальность относительно конкурентов:**
- Mealime/Yummly дают рецепты, но без модульности (один рецепт = одно блюдо).
- ChatGPT генерирует меню, но не связывает его с заготовками и хранением.
- **Modular Chef:** pull-модель «выбираешь желания → система достраивает» + связка модулей в 15+ блюд + карта хранения (холодильник/морозилка/вакуум).

**Две роли в одном приложении:**
- **Шеф** — планирует меню, идёт в магазин, готовит впрок, раскладывает по контейнерам.
- **Гость** — открывает утром, видит «что есть сегодня», 2 минуты на сборку, кнопка «Готово».

## 2. Ключевая механика — 4 шага Шефа

### Шаг 1. «Хочу это есть»
Пользователь выбирает желания по 5 категориям:
- **Белки** (3–5 шт): курица, лосось, стейк, индейка, фрикадельки, рыба, креветки, тофу, `+ Своё`
- **Гарниры** (2–4 шт): рис, гречка, булгур, спагетти, картофель, кускус, `+ Своё`
- **Супы** (0–2 шт): сырный крем-суп, куриный с лапшой, томатный, тыквенный, грибной, `+ Своё`
- **Завтраки** (2–3 типа): овсянка в банке, сырники, омлет, каша, бутерброды, `+ Своё`
- **Мои блюда** — кастомные блюда и сочетания пользователя

Овощи и заправки система подбирает сама — пользователь не знает, что с чем сочетается.

### Шаг 2. «Что купить»
Автогенерация списка покупок на 2 недели, разделённого на **2 похода** (свежие овощи на 2 недели не купишь). Группировка по отделам магазина.

### Шаг 3. «Как разнообразно приготовить» — С ВЫБОРОМ СПОСОБА
Для каждого белка пользователь выбирает способ:
- **Курица:** `[Запечь 40мин] [Гриль 25мин] [Отварить 30мин] [Тушить 45мин]`
- **Лосось:** `[В фольге 20мин] [Гриль 15мин] [Слабосолёный 24ч]`
- **Стейк:** `[Сковорода 10мин] [Гриль 15мин]`

Система пересчитывает конвейер с учётом параллельных процессов (духовка + плита + нарезка).

### Шаг 4. «Как сохранить свежим» — KILLER FEATURE
**Карта хранения с конкретными позициями:**
- 🟩 **Холодильник** (3–4 дня): курица порции 1–3 → пн-ср, лосось 1–2 → пн-вт, рис → пн-ср, соусы, супы
- 🟦 **Морозилка** (на 2-ю неделю): курица 4–6 → разморозить в ср, индейка → чт, бешамель кубиками, томатный соус кубиками, бульоны
- 🟣 **Вакуум:** лосось 3–4 → до чт-пт, стейк → до ср

С подсказками: «Бешамель отлично замораживается кубиками, при разогреве добавь ложку молока», «Сделай соусов с запасом — заморозка 3 месяца, а времени столько же».

## 3. ИИ — один вызов в ядре

**Вход (Claude API, Sonnet):**
- Каталог модулей (JSON)
- Матрица сочетаемости
- Выбор пользователя (что хочет есть)
- Предпочтения (аллергии, не ест мясо/молочку и т.д.)

**Выход:** связанное меню на 14 дней (завтрак/обед/ужин), где:
- Каждый белок используется в 3–4 разных блюдах
- Один белок не повторяется 2 дня подряд в одном приёме пищи
- Вкусовые профили чередуются (азия → средиземноморье → русский → азия)
- Свежие овощи в начале недели, замороженные/запечённые в конце
- Время воскресной заготовки ≤ выбранного лимита (1ч / 2ч / 3ч+)

**Принцип:** не делаем ИИ-советчиков сочетаемости в каждом конструкторе. Один умный генератор в ядре.

## 6. Визуальный стиль

**Источник:** `design_input/chef/stitch_ux_ui/serene_purity/DESIGN.md` — система «Clinical Ethereal / The Curated Sanctuary».

- **Палитра:** powdery pinks + cool greys + restorative pistachio green
  - `surface` `#f8f9fb`
  - `surface_container_lowest` `#ffffff`
  - `primary` `#49655a` (мягкий пистачо)
  - `primary_container` `#cbe9dc`
  - `secondary_container` `#f0dede` (терракот/розовый)
  - `tertiary_container` `#fde5ec`
- **«No-Line Rule»:** запрещены 1px бордеры для секционирования — только тональные переходы фонов
- **Типографика:** Inter Rounded (Display tight letter-spacing -0.02em, Body в `#596064`)
- **Радиусы:** `xl` (1.5rem) для primary cards, никаких острых углов
- **Тени:** ambient `box-shadow: 0 12px 32px rgba(44, 51, 55, 0.04)` — никакого pure black
- **Иконки зон хранения:** 🟩 холодильник, 🟦 морозилка, 🟣 вакуум, 🟫 кладовая
- **Язык:** русский
- **Bottom nav** на всех экранах

## 8. Этапы работ (план чата)

### Этап 1a — Скаффолд Flutter-проекта (фундамент)
1. `flutter create modular_chef` в `D:\Desktop\modular_chef`
2. Добавить зависимости: `go_router`, `provider`, `google_fonts` (для Inter), `cached_network_image`, `flutter_svg`
3. Реализовать тему Clinical Ethereal: `ThemeData` с цветовой схемой, типографикой (Inter Rounded), радиусами, тенями. Глобальный запрет на 1px бордеры через стиль.
4. Каркас навигации:
   - Переключатель роли Шеф ⇄ Гость (где живёт — в профиле или верхнем баре)
   - Bottom nav Шефа: 5 пунктов (Меню / Покупки / Подготовка / Хранение / Профиль)
   - Bottom nav Гостя: 3 пункта (Сегодня / Неделя / Запасы)
5. Routing через `go_router`.

### Этап 1b — Порт 5 готовых макетов в Flutter
Перенести по образцу HTML-кода Stitch:
- `chef/serene_5` → `ShoppingListScreen` ✅
- `chef/serene_4` → `MyDishesScreen` ✅
- `guest/v4_1` → `AssembleDishScreen` ✅
- `guest/v4_3` → `InventoryScreen` ✅
- `guest/v4_4` → `TodayScreen` ✅

### Этап 1c — Дорисовать 4 недостающих экрана сразу в Flutter
1. **`TwoWeekMenuScreen` (Шеф)** — сетка 14 дней × 3 приёма, тогл «Неделя 1 / Неделя 2», свайп для замены блюда, бейдж «15 блюд из 6 модулей», кнопка «Утвердить». **КРИТИЧЕСКИЙ — без него флоу разорван.**
2. **`BuildMenuScreen` (Шеф, переделка `serene_1`)** — горизонтальный скролл на 6–8 карточек в каждой категории, явные чекмарки, `+ Своё`, секция «Мои блюда».
3. **`StorageMapScreen` (Шеф, переделка `serene_3`)** — конкретные позиции с днями: «Курица порции 1–3 → пн-ср», «Лосось → вакуум, до чт» с подсказками по каждой.
4. **`PrepDayScreen` шаг 1 (Шеф, дополнение к `serene_2`)** — для каждого белка чипы `[Запечь] [Гриль] [Отварить]`, после выбора — конвейер шага 2 пересчитывается.
5. **`MyWeekScreen` (Гость, на основе `guest/v4_2`)** — портируем как есть (уже готов).

### Этап 2 — Подготовка data-слоя
JSON-каталоги (живут в `assets/data/` Flutter-проекта и параллельно в репозитории бэка):
- `modules.json` — 100–150 базовых модулей (белки, гарниры, овощи, соусы, завтраки, супы) с тегами, временем приготовления, сроками хранения
- `pairings.json` — матрица сочетаемости (50–70 готовых троек: белок + гарнир + соус)
- `week_templates.json` — 4–5 шаблонов «вкусовых недель» (средиземноморская, азиатская, русская классика, микс)
- `storage_rules.json` — правила хранения

### Этап 3 — Промпт для генерации меню
Готовый промпт для Claude API (Sonnet), который принимает выбор пользователя и выдаёт связанное меню в JSON.

### Этап 4 — Архитектура БД
Таблицы: `users`, `weekly_menus`, `modules` (каталог), `shopping_lists`, `user_dishes`, `storage_items`. Миграции под Railway PostgreSQL.

### Этап 5 — Интеграция бэка
- FastAPI-эндпоинты: генерация меню, список покупок, обновление статусов хранения, библиотека «Мои блюда»
- Подключение Flutter к API через `dio`
- Деплой на Railway
