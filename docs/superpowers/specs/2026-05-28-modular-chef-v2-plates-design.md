## 1. Зачем v2 (что показало тестирование)

MVP (Stages 1–5) задеплоен и работает: Flutter APK → FastAPI на Railway → OpenAI генерит меню. Тестирование на телефоне выявило, что **продукт работает, но непонятен**:

1. Переключение ролей стрелкой ⇄ — неочевидно
2. Непонятен **принцип** сборки меню — нет ментальной рамки
3. Овощи и соусы скрыты — пользователь не видит, что подобрала система
4. Нет подсказок сочетаемости
5. Нет перекусов
6. Список покупок не связан с тем, что уже есть
7. Подготовка только для белков (нет овощей/салатов/супов)
8. Гость пассивен — только потребляет готовое

## 2. Ключевой сдвиг концепции

### Что НЕ меняется — лёгкость модульного входа

Исходный «обратный алгоритм» (модули → меню) остаётся ядром. Шеф по-прежнему **просто тыкает желания**, система достраивает. Вход не усложняется.

### Что меняется — «тарелка» как форма результата

**«Тарелка» ≠ ручная сборка.** Это:
- **форма показа** результата — целое блюдо `белок + гарнир + овощ + соус` вместо огрызка `белок + гарнир`;
- **видимость** — овощи и соусы, которые подбирает система, теперь видны;
- **опциональная правка** — можно поменять компонент, но не обязательно.

### Принцип: Progressive Disclosure

| Уровень | Кто | Что делает |
|---------|-----|-----------|
| По умолчанию | торопится | тык ингредиентов → система собрала → ничего не трогает |
| Глубокий | придирчив | тапнул тарелку → поменял овощ/соус/гарнир |
| Профиль | один раз | задал предпочтения (не ем молочку, люблю острое) → авто-подбор их учитывает |

**Предпочтения снижают необходимость править**, ручная правка — escape hatch, а не рутина.

### Разный масштаб Шефа и Гостя

| | Масштаб | Сборка |
|---|---------|--------|
| **Шеф** | планирует **42 приёма** на 2 недели | ❌ ручная по каждому = ад → система генерит, правка точечная и опциональная |
| **Гость** | собирает **1 тарелку** здесь и сейчас из запасов | ✅ ручная сборка уместна — это 20 секунд и приятно |

## 3. Модель данных «Тарелка»

Текущий `PlannedMeal { title, moduleIds[], reheatMinutes, fromContainer }` слишком плоский — нельзя показать роли и точечно править.

Новый `PlannedMeal`:

```
PlannedMeal {
  title:         "Курица гриль + рис + брокколи + йогуртовый соус"
  kind:          main | breakfast | soup | snack
  components: [
    { moduleId: "chicken_breast", role: protein,    name, emoji },
    { moduleId: "rice",           role: side,        name, emoji },
    { moduleId: "broccoli",       role: vegetable,   name, emoji },
    { moduleId: "yogurt_sauce",   role: sauce,       name, emoji },
  ]
  reheatMinutes, fromContainer
}
```

Роли (`role`): `protein | side | vegetable | sauce | base | standalone`.
- **main** = protein + side + vegetable + sauce
- **breakfast** = standalone (овсянка) [+ topping]
- **soup** = standalone [+ base: хлеб]
- **snack** = standalone

Правка = замена компонента роли X на другой модуль той же роли и совместимой кухни.

## 4. Сочетаемость (подсказки)

Чтобы подсказки были, но не раздражали:

- У каждого модуля и pairing'а есть **тег кухни**: `mediterranean | asian | russian | italian | neutral`.
- **Авто-подбор** всегда берёт совместимые (одна кухня или `neutral`) — плохих комбо система сама не предложит.
- При **ручной** правке, если пользователь выбрал клеш (соус другой кухни): мягкая подсказка
  > «Йогуртовый соус — средиземноморский, а гарнир азиатский. Лучше зайдёт тахини 🌰»
  Не блокируем — только советуем.

Матрица `pairings.json` расширяется: сейчас 26 троек, нужно ~60–80 + теги кухонь на овощах/соусах.

**Базу наполняю я** (по кулинарной логике). Плюс **шеф постепенно добавляет свои любимые сочетания** — они сохраняются (рядом с «Мои блюда») и всегда учитываются генератором как приоритетные. Так матрица растёт под вкус конкретного пользователя.

## 5. Экраны: сейчас → станет

### 5.1 Шеф · «Собери меню» (`menu_screen.dart`)
| Сейчас | Станет |
|--------|--------|
| Плоские списки галочками, «Мои блюда» прячутся в скролле | Вводный блок «Как это работает» (3 шага). Секции: Белки / Гарниры / Супы / Завтраки / **Перекусы** (опционально) / **Мои блюда** (отдельной видимой секцией, не в скролле). Вход тот же — тык. |

**Перекусы — опциональны.** Шеф может добавить или пропустить. При добавлении система предлагает **вариации двух типов**:
- 🛒 **Купить готовое** — орехи, йогурт, творог, фрукты, протеин-бар → попадают в список покупок.
- 🍳 **Приготовить** — энергетические шарики, запечённые чипсы, гранола → попадают в «Подготовку».

### 5.2 Шеф · «Меню на 2 недели» (`two_week_menu_screen.dart`)
| Сейчас | Станет |
|--------|--------|
| Строка `белок + гарнир`, замена из плоского списка | Полная **тарелка** (белок+гарнир+овощ+соус), показаны все компоненты. **4-й слот перекуса** (опционально). Три уровня правки (см. ниже). |

**Три уровня правки — решает проблему «42 тарелки точечно править = овердофига»:**

1. **Предпочтения (подсвечены сверху).** Над меню — чипы «учтено: без молочки ✓, люблю острое ✓». Тап → редактировать профиль → меню перегенерится с учётом. Это первый и главный рычаг — настроил один раз, дальше править почти не нужно.

2. **Обзор по компонентам (батч-правка) — главный новый инструмент.** Панель «Обзор меню» группирует все 42 тарелки **по типу компонента**, чтобы не открывать каждую:
   ```
   🥛 Соусы:   йогуртовый ×8 · томатный ×6 · песто ×4   [просмотреть / заменить]
   🥦 Овощи:   брокколи ×9 · салат ×7 · цукини ×5        [просмотреть / заменить]
   🍚 Гарниры: рис ×10 · гречка ×8 · булгур ×6           [просмотреть / заменить]
   ```
   Тап по типу → видишь где используется → можно **«заменить везде»** (например, весь йогуртовый → тахини) или в выбранных днях. Так шеф «просматривает соусы» и правит их пачкой, не открывая 42 карточки.

3. **Точечная правка (escape hatch).** Тап на отдельную тарелку → поменять любой компонент только в ней. Для перфекционистов, по желанию.

### 5.3 Гость · «Сегодня» — главный хаб (`today_screen.dart`)

Гость живёт **сегодняшним днём** — «хочу поесть сейчас», что будет завтра не важно. «Сегодня» становится центром гостевого опыта:

| Сейчас | Станет |
|--------|--------|
| Просмотр 3 приёмов на сегодня | **Планирование + сборка дня.** 4 слота (☀️завтрак / 🌞обед / 🌙ужин / 🥨перекус). По каждому слоту можно: <br>• **собрать сейчас** → переход к сборке тарелки из запасов <br>• **отказаться** от приёма («сегодня не ужинаю, иду гулять») <br>• **запланировать с утра** весь день сразу, потом поменять или оставить <br>Собранное закрепляется в «Сегодня» (быстрый доступ). |

### 5.3.1 Гость · «Собрать тарелку» (`assemble_dish_screen.dart`)
Открывается из слота в «Сегодня». **Активная сборка**: видишь что в запасах → собираешь тарелку из доступного → подсказки сочетаемости («к этому есть свежий салат, добавь»). Кнопка «Готово» → тарелка закрепляется в слоте «Сегодня».

### 5.4 Шеф · «Список покупок» (`shopping_screen.dart`)
| Сейчас | Станет |
|--------|--------|
| Просто список с чекбоксами | Две группы: **«Купить»** и **«Уже есть»**. MVP: ручной свайп «есть». Будущее: авто из `storage_items` (таблица уже в БД). Помогает реально ходить с ним в магазин. |

### 5.5 Шеф · «Подготовка» (`prep_screen.dart`)
| Сейчас | Станет |
|--------|--------|
| Только белки (курица/лосось/стейк) | **Расширение на все типы**: белки + овощи + салаты + супы. Каждая позиция тапается → шит с деталями способа (шаги, нюансы) + **как хранить** (зона, срок). Больше способов + кастомные. |

### 5.6 Профиль · «Предпочтения» (`profile_screen.dart`, сейчас disabled)
| Сейчас | Станет |
|--------|--------|
| Пункт неактивен | **Активный экран**: аллергии (молочка, глютен…), не ем (мясо, рыба…), люблю/не люблю (острое, кислое). Передаётся в промпт → авто-подбор учитывает. **Учтённые предпочтения подсвечиваются на экране меню** (чипами), чтобы шеф видел, что применено, и мог поправить. |

### 5.7 Переключение ролей (`role_switcher.dart`)
| Сейчас | Станет |
|--------|--------|
| Иконка `swap_horiz` ⇄ | **Сегмент-переключатель** сверху: `[ 👨‍🍳 Шеф \| 🍽 Гость ]` с подписями. Видно оба состояния. |

### 5.8 Гость · «Моя неделя» — УБИРАЕМ (`week_screen.dart`)
Удаляем. Гость думает «что поесть **сейчас**», горизонт недели ему не нужен. Гостевая навигация сокращается с 3 табов до **2: «Сегодня» + «Запасы»**. `week_screen.dart` и его пункт в `GuestShell` удаляются.

## 5A. Новая дизайн-система «Лён и глина» (заменяет Clinical Ethereal)

Выбрана на ревью 2026-05-28 по сгенерированным макетам. Тёплая, выцветшая, природная, взрослая — уходим от зелёного «детского» Clinical Ethereal.

### Палитра (точные hex)
| Токен | Hex | Назначение |
|-------|-----|-----------|
| `bg` (льняной фон) | `#EDE6DA` | основной фон экранов |
| `bgPage` | `#E8E0D2` | секции/подложки |
| `surface` (карточка) | `#FBF6EE` | карточки, плавающие поверхности |
| `surfaceAlt` | `#FFFFFF` | фото-подложки |
| `primary` (сухая глина) | `#AE6A4D` | акцент, кнопки, активное состояние |
| `primaryDeep` | `#8F5238` | нажатие, текст на светлой глине |
| `secondary` (олива-тауп) | `#8A7E5E` | вторичные акценты |
| `text` (эспрессо) | `#2E2620` | основной текст, заголовки |
| `textMuted` | `#8A7C6C` | вторичный текст, подписи |
| `tagBg` | `#F0E7D7` | фон тегов |
| `freshHint` (приглушённый шалфей) | `#7E8A6E` | редкий «свежий» индикатор |

Принцип: выцветшая, ненасыщенная гамма. Один акцент (глина) делает работу, остальное — тёплый воздух.

### Типографика
- **Заголовки/display** — `Fraunces` (мягкий редакторский serif, тёплый, премиальный) — большие заголовки «Сегодня», названия экранов. Это даёт «дорогой журнальный» вид.
- **Body / UI** — `Inter` (чистый, читаемый) — текст, кнопки, подписи.
- Оба есть в `google_fonts`. Контраст serif-заголовок + sans-body — ключ к взрослому ощущению.

### Форма и компоненты
- **Радиусы**: карточки `24px`, фото внутри `18px`, кнопки `14px` (мягкий прямоугольник, **не толстая пилюля**), теги — pill `999px` (но маленькие).
- **Кнопки**: заливка `primary` (глина), текст `surface`, умеренная высота, label `Inter w600`. Вторичная — ghost/outline тёплым. Никаких ярких толстых пилюль.
- **Выделение**: мягкая заливка `primary` 12% + лёгкий `scale(0.98)` при тапе, без жёстких рамок.
- **Тени**: тёплые, низкие — `0 8px 24px rgba(46,38,32,0.06)`. Никакого pure black.
- **Фактура**: лёгкое зерно/бумага на фонах, очень деликатно.

### Изображения
- Фото блюд: top-down, тёплый естественный свет, единый стиль (генерим через image-gen, кэшируем).
- Атмосферные заголовки: мягкое небо/облака в тёплом свете, fade в льняной фон.

### Переходы
- Пружинные (spring) анимации появления.
- Shared-element: фото блюда плавно раскрывается на весь экран при открытии.
- Parallax: небо в заголовке мягко смещается при скролле.
- Soft fade-up: карточки появляются со сдвигом.
